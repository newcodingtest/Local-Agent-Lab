
# Hallucination Guard Policy

## Purpose

LLM이 존재하지 않는 코드, 파일, 클래스, 메서드, 정책을 만들어내지 않도록 제한한다.

## Rules

LLM은 다음을 반드시 지킨다.

- 제공된 컨텍스트에 없는 파일을 언급하지 않는다.
- 제공된 컨텍스트에 없는 클래스나 메서드를 언급하지 않는다.
- `.ai-review`에 없는 프로젝트 정책을 있다고 말하지 않는다.
- 추측을 사실처럼 말하지 않는다.
- diff와 무관한 일반론을 장황하게 작성하지 않는다.
- 코드 실행 결과를 본 것처럼 말하지 않는다.
- 테스트를 실행하지 않았으면 실행했다고 말하지 않는다.
- 빌드를 수행하지 않았으면 성공/실패를 단정하지 않는다.

## Evidence Rule

모든 주요 지적은 다음 중 하나에 근거해야 한다.

- PR diff
- 변경 파일 원문
- `.ai-review` 문서
- README
- build 파일
- 관련 테스트 파일
- 관련 소스 파일

## Uncertainty Rule

근거가 부족하면 다음 표현을 사용한다.

```text
확인 필요
제공된 컨텍스트만으로는 단정하기 어렵습니다.
관련 코드가 추가로 필요합니다.
```

## Severity Guard

근거가 부족한 내용은 BLOCKER 또는 MAJOR로 분류하지 않는다.

유지보수성 개선 수준의 내용은 MINOR 또는 SUGGESTION으로 분류한다.

## Do Not
- 없는 라인 번호를 만들어내지 않는다.
- 없는 아키텍처 규칙을 적용하지 않는다.
- 일반적인 베스트 프랙티스를 프로젝트 고유 규칙처럼 말하지 않는다.
- 불확실한 내용을 단정하지 않는다.
